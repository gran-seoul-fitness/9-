# 혼잡도 API 서버 (로컬용 스타터)

`prototypes/gymmap.html`의 "실시간 혼잡도" 표시는 원래 코드에 박혀있는 샘플 숫자예요.
이 폴더는 그 샘플 숫자를, 입퇴실 기록으로부터 계산한 실제 값으로 바꿔치기하는 아주
작은 로컬 서버예요.

## 실행 방법

```bash
cd backend
node server.js
```

`http://localhost:8787/api/occupancy` 접속해서 JSON이 나오면 정상이에요.
이 상태에서 `prototypes/gymmap.html`을 열면(같은 컴퓨터에서), 자동으로 이 서버를
찾아서 실제 숫자를 보여주고, 서버가 꺼져있으면 예전처럼 샘플 숫자로 조용히
돌아가요 — 그러니 이 서버를 꼭 켜두지 않아도 프로토타입 자체는 항상 잘 동작해요.

## 실제 장치 데이터 형식

관리자 화면의 "시설물 이용현황" 리포트를 확인해보니 컬럼이 이래요:

```
순번, 회원정보, 이용락카, 키번호, 성별, 회원구분, 이용대상, 입장시각, 퇴실시각
```

- **한 행 = 한 번의 방문(입장~퇴실)** 이에요. 로그가 아니라 방문 단위 레코드고요.
- **퇴실시각이 비어있으면 아직 안에 있는 사람**이에요 — 이 개수를 세서 현재 총
  인원을 계산해요. (`data/checkins.csv`가 이미 이 형식으로 맞춰져 있어요.)
- **이용락카는 "여자사우나"/"남자사우나"** 처럼 성별 락커 구분이에요. 웨이트존,
  유산소존, GX, 스트레칭존처럼 운동 구역 정보는 이 장치로는 알 수 없어요.

## 실제 데이터로 바꾸는 방법

1. 관리자 화면에서 **[Excel]** 또는 **[Text]** 내보내기 버튼으로 실제 파일을
   받아주세요. (`[Print]`/`[Html]`은 화면 인쇄용이라 파싱하기 번거로워요.)
2. `.xlsx`로 받아졌다면 엑셀에서 "다른 이름으로 저장 → CSV(쉼표로 분리)"로 한 번
   변환해주세요.
3. 그 파일을 `data/checkins.csv` 자리에 덮어써주세요. (컬럼 구성이 위와 같다면
   그대로 동작할 거예요.)
4. 실제로 열어보니 컬럼 순서/이름이 다르거나 한글이 깨져 보이면(EUC-KR 인코딩인
   경우가 흔해요) 그 파일을 저에게 보내주시면 정확히 맞춰드릴게요.
5. 서버는 요청이 올 때마다 파일을 새로 읽기 때문에, 이 파일 내용만 최신으로
   유지되면 재시작 없이 최신값이 반영돼요.

## 알아둘 점: 구역별 인원은 추정치예요

이 장치는 성별 락커(사우나) 단위로만 입퇴실을 구분하지, 웨이트존/유산소존/GX/
스트레칭존처럼 헬스장 내부 어디에 있는지는 감지하지 못해요. 그래서:

- **전체 인원(`totalCount`)** 은 퇴실시각이 빈 행의 개수로 계산한 **실제 값**이에요.
- **구역별 인원** 은 `config.json`의 구역별 정원 비율로 나눠 계산한 **추정치**예요.
  (구역마다 실제 감지기가 따로 생기기 전까지는 이 부분은 항상 추정일 수밖에 없어요.)

## 자동 갱신이 필요하다면

관리자 화면에 "예약 내보내기" 기능이 있다면, 그 기능이 이 폴더의
`data/checkins.csv` 자리에 파일을 주기적으로 떨궈주도록 설정하면 이 서버가 계속
최신값을 돌려줘요. 그런 기능이 없다면, 당분간은 새 내보내기 파일을 이 경로에
수동으로 복사해주는 방식으로 "완전 실시간"은 아니지만 "주기적으로 갱신되는" 값을
보여줄 수 있어요.

## 어디서 돌려야 하나요?

지금은 `http://localhost:8787` 로만 동작하는 **로컬 전용** 서버예요. 장치가 설치된
그 컴퓨터에서 이 서버를 켜두고, 같은 컴퓨터(또는 같은 매장 내부망)에서
`gymmap.html`을 열면 바로 붙어요. 나중에 실제 서비스로 배포하려면(인터넷 어디서나
접속) 이 서버를 클라우드/사설 서버에 올리고 `prototypes/gymmap.html`의
`OCCUPANCY_API_URL` 값을 그 주소로 바꿔주면 돼요.
