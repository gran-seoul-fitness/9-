# 혼잡도 API 서버 (로컬용 스타터)

`prototypes/gymmap.html`의 "실시간 혼잡도" 표시는 원래 코드에 박혀있는 샘플 숫자예요.
이 폴더는 그 샘플 숫자를, 입퇴실 기록 CSV로부터 계산한 실제 값으로 바꿔치기하는
아주 작은 로컬 서버예요.

## 실행 방법

```bash
cd backend
node server.js
```

`http://localhost:8787/api/occupancy` 접속해서 JSON이 나오면 정상이에요.
이 상태에서 `prototypes/gymmap.html`을 열면(같은 컴퓨터에서), 자동으로 이 서버를
찾아서 실제 숫자를 보여주고, 서버가 꺼져있으면 예전처럼 샘플 숫자로 조용히
돌아가요 — 그러니 이 서버를 꼭 켜두지 않아도 프로토타입 자체는 항상 잘 동작해요.

## 실제 장치 데이터로 바꾸는 방법

1. `data/checkins.csv` 를 RNS에서 내보낸 실제 파일로 덮어써주세요. (파일명 `checkins.csv` 유지)
2. 컬럼이 지금 샘플과 다르면(회원번호/시간/입실·퇴실 표시 방식 등), `server.js`의
   `parseCsv()` / `computeOccupancy()` 부분만 실제 컬럼명에 맞게 고치면 돼요.
   **실제 내보내기 파일 하나를 샘플로 공유해주시면 그 매칭 작업은 제가 해드릴게요.**
3. 서버는 요청이 올 때마다 `data/checkins.csv`를 새로 읽기 때문에, 이 파일 내용만
   최신으로 유지되면 별도 재시작 없이 최신값이 반영돼요.

## 알아둘 점: 구역별 인원은 대부분 "추정치"예요

입퇴실 장치가 보통 감지하는 건 "건물/매장에 몇 명이 들어와 있는가" 하나뿐이라,
웨이트존/유산소존/GX/스트레칭존처럼 안에서 어디 있는지까지는 이 장치 하나로는 알
수 없는 경우가 많아요. 그래서:

- **전체 인원(`totalCount`)** 은 CSV의 입실/퇴실 기록으로 계산한 **실제 값**이에요.
- **구역별 인원** 은 CSV에 구역 정보가 없으면 `config.json`의 구역별 정원 비율로
  나눠 계산한 **추정치**예요. (구역별로 실제 리더가 따로 있어서 CSV의 `zone`
  컬럼이 다 채워져 있다면, 그때는 추정 없이 실제 값을 그대로 써요.)

## 자동 갱신이 필요하다면

RNS 관리자 웹/소프트웨어에 "예약 내보내기" 기능이 있다면, 그 기능이 이 폴더의
`data/checkins.csv` 자리에 파일을 주기적으로 떨궈주도록 설정하면 이 서버가 계속
최신값을 돌려줘요. 그런 기능이 없다면, 당분간은 새 내보내기 파일을 이 경로에
수동으로 복사해주는 방식으로 "완전 실시간"은 아니지만 "주기적으로 갱신되는" 값을
보여줄 수 있어요.

## 어디서 돌려야 하나요?

지금은 `http://localhost:8787` 로만 동작하는 **로컬 전용** 서버예요. RNS 장치가
설치된 그 컴퓨터에서 이 서버를 켜두고, 같은 컴퓨터(또는 같은 매장 내부망)에서
`gymmap.html`을 열면 바로 붙어요. 나중에 실제 서비스로 배포하려면(인터넷 어디서나
접속) 이 서버를 클라우드/사설 서버에 올리고 `prototypes/gymmap.html`의
`OCCUPANCY_API_URL` 값을 그 주소로 바꿔주면 돼요.
